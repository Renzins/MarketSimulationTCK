Baltic Imbalance Regime Forecast

Six-hour ahead (24 × 15-minute) probability forecast of Baltic imbalance regimes — NEG (grid deficit), ZRO (balanced), POS (grid surplus) — and expected imbalance prices. The model (regime_v6_light_top100) lives in a separate private repository and runs on demand via GitHub Actions. Last forecast: —.

Forecast control

Enter the shared password and click Run forecast to dispatch a single workflow run. The page polls for completion (up to 15 minutes), refetches forecast.json and redraws the charts. It runs exactly once per click — there is no automatic refresh. Click Run forecast again whenever you want a fresh forecast. While a run is in flight the button becomes Cancel.

—

Private GitHub repository hosting the model and forecast.json. Edit the constants at the top of gh-run.js (shared with the Bid-data page) to point at your repo.

The password gates workflow dispatches server-side. It is never persisted to disk, browser storage or URL — it stays only in the masked field above and in memory during a run. Reload to clear it.

idle

Current run state and last-dispatch result. Wrong password → the workflow exits in ~5 s and shows "auth failed"; the displayed forecast stays at the last successful read.

Probability per horizon

Stacked bar per horizon (15-minute step). NEG = grid deficit (system needs upward energy), ZRO = balanced, POS = grid surplus (system needs downward energy). Heights sum to 1.

Expected imbalance price

Per-horizon expected imbalance price in two sets. Static (blue) uses each grid state's mean price over the whole rolling window; dynamic (orange) re-prices each horizon off its own day-ahead level (state × DA-price cell), so it tracks DA context. Within each set the solid line is the model-weighted expectation and the dashed line the calendar-only baseline (no model). Solid-vs-dashed is the value the model adds; blue-vs-orange is the day-ahead-context adjustment. (Dynamic lines appear once a fresh run emits them.)
